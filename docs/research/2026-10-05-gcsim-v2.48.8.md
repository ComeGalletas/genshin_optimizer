## Licence

- **AGPL-3.0-or-later since 2026-09-19**; versions up to and including
  v2.47.2 were MIT (`LICENSE-MIT` in the repository).
- What that means here (not legal advice): CLAUDE.md already has gcsim run as
  an external binary through a child process. Running the official,
  unmodified binary as a separate program doesn't put this repository under
  the AGPL. **What must not happen is copying gcsim source into this
  repository**, for example its GOOD-to-config converter
  (`ui/packages/ui/src/features/simulator/good/GOODToSrl.functions.ts`);
  config generation (5.5) is written here from the documented syntax.

## CLI (`cmd/gcsim/main.go`)

| Flag                  | Use here                                                        |
| --------------------- | --------------------------------------------------------------- |
| `-c <file>`           | the config to run (default `config.txt`)                        |
| `-out <file>`         | write the result as JSON                                        |
| `-gz`                 | gzip the JSON (needs `-out`); not needed                        |
| `-nb`                 | don't open a browser                                            |
| `-s`                  | serve results to the viewer (default off; keep off)             |
| `-version`            | print the version (git hash): what `sim:check` reads            |
| `-sample <file>`      | a sample (frame-by-frame) run, for reviewing drafted rotations  |
| `-substatOptim[Full]` | KQM substat optimisation; not used (we pass the real artifacts) |
| `-nr`                 | don't run (with `-sample` only)                                 |
| `-update`             | self-updater: never (the binary is pinned and verified)         |

Iterations, duration and workers are not flags: they are in the config's
`options` line.

## Config syntax (docs.gcsim.app, reference/config)

```
bennett char lvl=90/90 cons=5 talent=6,9,9;
bennett add weapon="aquilafavonia" refine=1 lvl=90/90;
bennett add set="noblesseoblige" count=4;
bennett add stats hp=4780 atk=311 er=0.518 hp%=0.466 cr=0.311 cd=0.265 em=42;
options iteration=1000 duration=90 swap_delay=14;
target lvl=100 resist=0.1 hp=999999999;
energy every interval=480,720 amount=1;
active bennett;
bennett skill, burst;
```

- **Units: fractions**, not percent: `cr=0.311` is 31.1% CRIT Rate, `er=0.518`,
  `hp%=0.466`, `resist=0.1`. The engine keeps percent (ADR-0023), so 5.5
  divides by 100 at this boundary, and tests it.
- Stat keys: `hp`, `atk`, `def`, `em`, `er`, `cr`, `cd`, `hp%`, `atk%`, `def%`,
  and one DMG bonus key per element: `pyro%`, `hydro%`, `anemo%`, `electro%`,
  `dendro%`, `cryo%`, `geo%`, `physical%`. Our single `elemental_dmg` maps to
  the goblet's element.
- `add stats` carries **only the artifacts' stat lines** (mains and subs):
  gcsim adds the character's base, the weapon and the set bonuses itself.
  So 5.5 passes the summed artifact lines, not our sheet totals.
- Names are lowercase, without separators: weapons `favoniussword`, sets
  `noblesseoblige`. Characters accept the full name the same way
  (`raidenshogun`, `kaedeharakazuha`, `kukishinobu`, `kamisatoayaka`) as well
  as short forms (`raiden`, `kazuha`); the map is `pkg/shortcut/character.dm.go`.
  Our dataset keys with the non-letters removed are accepted.
- `target` (`lvl`, `resist`, `hp`, `pos`, `radius`, …) and `energy` lines carry
  the enemy and the particle assumptions; the rotation is the action list
  after `active`.

## Results (`protos/model/result.proto`, `-out` JSON)

- `statistics.dps`: `{ min, max, mean, sd }` per iteration; `statistics.iterations`.
- `statistics.character_dps[]`: per character, in party order.
- `statistics.source_reactions[]`, `statistics.total_source_energy[]`,
  `statistics.end_stats[].ending_energy`, `statistics.field_time[]`.
- `statistics.warnings`: `insufficient_energy`, `insufficient_stamina`,
  `swap_cd`, `skill_cd`, `burst_cd`, `dash_cd`, `target_overlap` (booleans),
  and `statistics.failed_actions[]` with how often each happened.
- `character_details[]`: `name`, `level`, `cons`, `weapon`, `talents`, `sets`,
  and **`stats` / `snapshot`** arrays: the final stats gcsim computed, which
  is what 5.5's unit test compares with our totals.
- `incomplete_characters[]`: characters gcsim knows only partly: a run with
  any is flagged, not trusted.
- `sim_version`, `build_date`, `schema_version`: recorded with every cached
  result (5.4 keys the cache on config plus version).

## GOOD import

PLAN assumed gcsim imports GOOD directly. **The CLI doesn't**: GOOD import
exists only in the web UI (`ui/packages/ui/src/features/simulator/good/`),
which turns GOOD into a config in the browser. So 5.5's cross-check is
against the stats gcsim reports for our generated config
(`character_details[].stats`), not against its importer, whose code we
can't reuse anyway (licence, above).
